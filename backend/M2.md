# M2 runbook — scraping, worker and review queue

M2 ingests merchant listings into a raw snapshot audit trail, stages them, publishes
matched offers, and appends EGP price history. It is deliberately isolated from the
public catalog contract in `app/api/v1/products.py`.

> M3 extends the review queue with reviewer roles and matcher suggestions; see
> `M3.md`. Scraper health and manual triggering remain admin-only.

## Components

| Component | Location | Purpose |
|---|---|---|
| Models / migration | `app/models/scraping.py`, `alembic/versions/0002_scraping.py` | `raw_snapshots`, `staging_listings`, `scraper_runs` |
| Adapters | `app/scrapers/` | Sigma, Compumarts, Nekhely and 2B via httpx/selectolax; robots-checked category pages, identifying UA, throttle, `Retry-After`, dynamic pagination |
| Pipeline | `app/services/ingestion.py` | dedupe → stage → match → offers/price history → ghost marking |
| Monitoring | `app/services/monitoring.py` | run-based alerts, structured logs, optional webhook |
| Worker | `app/workers/` | arq tasks + daily cron |
| Review API | `app/api/v1/review.py` | admin queue, match/reject, scraper health, manual scrape |

## Configuration

Copy `backend/.env.example` to `backend/.env`. M2 adds:

```dotenv
SCRAPER_DELAY_SECONDS=1.0
SCRAPER_TIMEOUT_SECONDS=15.0
SCRAPER_MAX_RETRIES=2
STALE_AFTER_HOURS=24
SCRAPE_CRON_HOUR=2          # UTC
SCRAPE_CRON_MINUTE=0
RECOMPUTE_CRON_MINUTE=30

# Alerts are always logged; the webhook is optional.
SCRAPER_ALERT_WEBHOOK_URL=
SCRAPER_ALERT_FAILURE_LIMIT=2
SCRAPER_ALERT_THROTTLE_LIMIT=3
SCRAPER_ALERT_DROP_RATIO=0.5

# Optional Web Bot Auth for Compumarts. Both values are required.
WEB_BOT_AUTH_AGENT_URL=
WEB_BOT_AUTH_PRIVATE_KEY=
WEB_BOT_AUTH_KEY_ID=          # optional; derived from the JWK thumbprint
WEB_BOT_AUTH_EXPIRES_SECONDS=300
```

## Run locally

```bash
docker compose up --build
```

The `api` service runs `alembic upgrade head` and the seed script before starting
Uvicorn. The `worker` service runs:

```bash
arq app.workers.WorkerSettings
```

Default schedule (UTC): `scrape_all` at 02:00, `recompute_offers_job` at 02:30.
`scrape_all` also recomputes offers at the end of its own run; the second cron keeps
ghost detection working even if that scrape fails.

`tests/test_cron_schedule.py` verifies both jobs are registered, that arq
calculates the next fire time from the configured hour/minute, and that arq's
`run_cron()` actually enqueues both jobs when due (using a fake Redis pool, so no
services are needed). To observe the same firing against live Redis, start a
one-off worker two minutes ahead of the clock (Docker/Redis required):

```bash
eval "$(python -c 'from datetime import UTC, datetime, timedelta; t = datetime.now(UTC) + timedelta(minutes=2); print(f"H={t.hour} M={t.minute}")')"
docker compose run --rm \
  -e SCRAPE_CRON_HOUR="$H" -e SCRAPE_CRON_MINUTE="$M" \
  -e RECOMPUTE_CRON_MINUTE="$M" -e SCRAPER_DELAY_SECONDS=0 \
  -e SCRAPER_MAX_RETRIES=0 worker
```

Wait for `worker_scrape_complete` in the log, then stop with Ctrl-C. The cron
values are read when the worker imports `app.workers`, so the container must be
started with the overrides (a running worker will not pick them up).

## Manual operations (admin token required)

```bash
# Enqueue scrape_all; returns {"job_id": "...", "status": "queued"}
curl -X POST http://localhost:8000/api/v1/admin/scrape/run \
  -H "Authorization: Bearer $ADMIN_TOKEN"

# Low-confidence / unmatched queue
curl "http://localhost:8000/api/v1/admin/review/listings?status=unmatched" \
  -H "Authorization: Bearer $ADMIN_TOKEN"

# Approve a match (recompute_offers is called automatically)
curl -X POST http://localhost:8000/api/v1/admin/review/listings/123/match \
  -H "Authorization: Bearer $ADMIN_TOKEN" -H 'Content-Type: application/json' \
  -d '{"product_id": 7}'

# Reject; the offer is no longer refreshed and will ghost after STALE_AFTER_HOURS
curl -X POST http://localhost:8000/api/v1/admin/review/listings/123/reject \
  -H "Authorization: Bearer $ADMIN_TOKEN"

# Per-merchant health, counters and alerts in the last 24h
curl http://localhost:8000/api/v1/admin/scrapers/health \
  -H "Authorization: Bearer $ADMIN_TOKEN"
```

Public price history is unchanged: `GET /api/v1/products/{id}/price-history`.

## Data rules

- A new `raw_snapshots` row is written only when the URL + SHA-256 checksum differ.
- Staging rows upsert on `(merchant_id, external_id)`; one bad card is skipped.
- Implausible prices are skipped via a per-adapter `min_price_egp` floor (EGP 100),
  enforced in every parse path including the shared fallback parser. Compumarts and
  Nekhely both publish `0`/`1 EGP` placeholders on sold-out cards; without the floor
  they could become bogus primary offers. See
  `tests/fixtures/compumarts_placeholder_price_real.html`.
- `price_history` gets a new row only when price or stock changes, or when an offer
  becomes stale (`source="scraper"` vs `source="ghost"`).
- Offers not observed for `STALE_AFTER_HOURS` are marked `in_stock=False`.
- Admin/reviewer roles still live in Postgres; Firebase owns credentials.

## Monitoring and alerts

`ScraperRun` now records `throttled_responses`, `fetch_failures` and
`parse_failures` in addition to status and listing counts. Migration `0004` adds
those counters; existing rows default to 0.

`app/services/monitoring.py` evaluates all active merchants that have a registered
adapter and emits these codes:

| Code | Trigger |
|---|---|
| `NO_RECENT_RUN` | No run within `STALE_AFTER_HOURS` (24h by default) |
| `FAILED_RUNS` | At least `SCRAPER_ALERT_FAILURE_LIMIT` failed runs in 24h |
| `THROTTLED` | At least `SCRAPER_ALERT_THROTTLE_LIMIT` 429/503 responses in 24h |
| `FETCH_FAILURES` / `PARSE_FAILURES` | Page-level failures at or above the failure limit |
| `SELECTOR_DRIFT` | New snapshots yielded zero listings |
| `LISTING_DROP` | Latest count below `SCRAPER_ALERT_DROP_RATIO` × the 7-day median |

Alerts are always logged as `scraper_alert`. If `SCRAPER_ALERT_WEBHOOK_URL` is set,
the same JSON is POSTed to it; webhook failures are logged and never fail a scrape.
`scrape_all` evaluates and emits alerts after recomputing offers and includes an
`alerts` count in its result. The health endpoint exposes `alerts`, `throttles_24h`,
`fetch_failures_24h` and `parse_failures_24h` alongside the existing fields.

## Web Bot Auth (Compumarts)

Compumarts requires identifiable automated traffic. Every request it makes carries
`User-Agent: Tagme3aPriceBot/1.0 (+https://github.com/Whiteman777/Tagme3a)`. When an
operator supplies a key, the adapter also signs each request (including `robots.txt`)
using `draft-ietf-webbotauth-httpsig-protocol-01` / RFC 9421:

- `Signature-Agent: wba="https://<agent-host>/.well-known/http-message-signatures-directory"`
- `Signature-Input` covering `@method`, `@target-uri`, `@authority`, the matching
  `signature-agent` dictionary member, plus `created`, `expires`, `keyid`, `alg`,
  `nonce`, and `tag="web-bot-auth"`
- `Signature` produced with Ed25519 (or P-256/ES256); never a shared secret

Signing is **off by default** and fails closed: setting only one of
`WEB_BOT_AUTH_AGENT_URL` / `WEB_BOT_AUTH_PRIVATE_KEY` raises a configuration error
when the Compumarts adapter is constructed. The agent URL must be absolute HTTPS.

Owner setup (cannot be completed inside this repository):

```bash
# On the worker host; keep the private key outside git and mode 0600.
uv run python -m scripts.generate_web_bot_auth_key \
  --out-dir /etc/tagme3a/web-bot-auth --days 90
```

Publish `http-message-signatures-directory.json` at the `WEB_BOT_AUTH_AGENT_URL`
over HTTPS with `Content-Type: application/http-message-signatures-directory+json`,
set `WEB_BOT_AUTH_PRIVATE_KEY` to the private key path (or inline PEM), restart the
worker, and confirm `tests/test_web_bot_auth.py` plus a live signed request. Rotate
by generating a new key before the directory `exp`, publishing both keys briefly,
then switching the private key and removing the old JWK. Contact details, agent
policy, and any merchant allowlisting still require the Compumarts owner.

## Real Sigma pages

Observed on 2026-11-27 (public pages only):

- `robots.txt` allows `/en/*` and disallows `/api/`, `/admin/`, checkout and account
  paths. The adapter therefore reads server-rendered category HTML and never calls
  the site's JSON API.
- No separate Terms page was linked; the footer only exposes privacy, return,
  shipping and warranty policies. Re-check before production use.
- Category URLs come from `https://sigma-computer.com/sitemap.xml`. The default
  adapter URL is the Laptops category
  (`/en/category/9f5039de-5c80-46f3-9fe4-6e8f94189b8c`); other category IDs from
  the sitemap can be passed to `scrape()` / `run_merchant()` as needed. Category
  URLs redirect to an allowed `/en/search?filters=...` page. The first page yields
  17 cards and the page embeds `totalPages`. `SigmaScraper.additional_pages()`
  discovers those page links from HTML and follows at most 3 pages per seed URL;
  the ingestion queue dedupes repeat targets. No disallowed `/api/` route is used.
- `SigmaScraper.listing_urls()` adds robots-allowed public searches for actual
  components: Ryzen 5 7600, Core i5 14600K, Ryzen 7 7800X3D, graphics card,
  motherboard, DDR5, SSD and power supply. These were confirmed live to return
  CPUs and GPUs (e.g. Ryzen 5 7600 at EGP 8,999 and a Palit RTX 5070 Ti at
  EGP 73,000). `run_merchant()` now stages one snapshot per page and aggregates
  the run counts.
- Each card is a titled `/en/item?id=<slug>` anchor with `p.font-bold` for the
  current EGP price, optional `p.line-through` for the old price, and an
  `#badges-container` that displays `Out Of Stock` when applicable. Verbatim card
  markup is kept in `tests/fixtures/sigma_listing_real.html` and
  `tests/fixtures/sigma_listing_oos_real.html`.

## Compumarts real pages

Observed on 2026-11-27 (public HTML only):

- Shopify storefront. `robots.txt` allows `/collections/*` and `/products/*` and
  disallows cart, checkout, account, admin and AJAX surfaces. The adapter only
  reads collection HTML.
- `agents.md` asks agent traffic to identify itself (Web Bot Auth) and recommends
  UCP/MCP. UCP catalog tools are available but require a publicly reachable agent
  profile, which is not configured here. Per operator decision, the adapter uses
  an identifying `Tagme3aPriceBot/1.0` User-Agent instead of browser
  impersonation. Client-side Web Bot Auth signing is implemented (see above) but
  stays disabled until the owner publishes a public HTTPS key directory and the
  worker is given the matching private key.
- Collection URLs come from `/sitemap_collections_1.xml`. The adapter covers eight
  component collections (CPU, GPU, motherboard, RAM, SSD, PSU, case, prebuilt PCs).
  `additional_pages()` follows Shopify's published page links up to each collection's
  real last page (cap 14); observed maxima are 4, 11, 14, 4, 2, 6, 11 and 1.
- Cards are `<product-card>` elements with `p.card__title a.card-link` for the
  title/link, `.price__current .js-value` for EGP price, `[data-product-id]` for
  a stable ID, and `.product-label--sold-out` for stock. Cards without a price
  (e.g. "Available in PC Builder only") are skipped. Verbatim markup is kept in
  `tests/fixtures/compumarts_listing_real.html` and
  `tests/fixtures/compumarts_gpu_real.html`.

## Nekhely real pages

Observed on 2026-11-27 (public HTML only):

- The seeded `elnekhely.com` domain is parked (Searchvity frameset; crawler UAs get
  HTTP 466), so the merchant now points at the live store
  `https://www.elnekhelytechnology.com`. Its `robots.txt` allows category HTML and
  disallows only one product URL, which the adapter never requests.
- OpenCart categories: processors, graphics-card, motherboards, ram, ssd,
  power-supply, cases and laptop. `ul.pagination a[href]` links are discovered per
  category and capped at 6 pages.
- Cards are `div.product-layout[data-product-id]`, with titles in
  `div.caption div.name > a`, prices in `.price .price-new` (fallback
  `.price .price-normal`) and stock in `div.stats .stat-2 span:last-child`.
  Verbatim markup is kept in `tests/fixtures/nekhely_listing_real.html`.

## 2B real pages

Observed on 2026-11-27 (public HTML only):

- Amazon.eg was removed: its Conditions of Use §3/§5 ban automated price collection
  into a database without written consent and `/gp/offer-listing` is
  robots-disallowed. 2B (توبي) replaces it in the seed and mock catalog.
- `robots.txt` allows clean `.html` category URLs and `?p=N` when it is the only
  query parameter. The adapter never requests filtered, sorted, cart, checkout or
  transactional paths; named crawler UAs are blocked, so it sends the identifying
  `Tagme3aPriceBot/1.0` UA on allowed pages only.
- Magento cards are `li.product-item`, with titles in `a.product-item-link`, prices
  in `[data-price-type="finalPrice"] .price` and IDs in `.price-box[data-product-id]`.
  `.pages a[href]` links drive pagination, capped at 6 pages. Verbatim markup is
  kept in `tests/fixtures/twob_listing_real.html`.
- The current catalog is laptop-heavy: the smoke run staged 267 listings but found
  0 curated matches, so 2B mainly adds coverage until more SKUs are curated.


Parser tests use saved HTML in `tests/fixtures/`, so they need no network. Live
scraping is not exercised by CI: selectors must be tuned against real Sigma,
Compumarts, Nekhely and 2B pages before production use.

was started directly and the pipeline was smoke tested end-to-end:

- `alembic upgrade head` reached `0002`; seed created 4 merchants and 15 products.
  Meilisearch was intentionally unreachable and the expected fallback warnings
